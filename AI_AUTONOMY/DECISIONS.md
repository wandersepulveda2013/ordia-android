| 2026-08-10 | El trabajo autónomo vive SOLO en `jules/autonomous-ordia`; `main` jamás recibe auto-merge. | Proteger la base estable de cambios no revisados por humanos. | Todo PR autónomo apunta a `jules/autonomous-ordia`; el humano revisa y decide si avanza a `main`. |
| 2026-08-10 | El rebuild de Codex se consolida en commits coherentes (tema por tema) y NO en un único commit gigante. | Historial legible y revisable. | 9 commits + rama de publicación `feature/ordia-total-rebuild-2026-08-10`. |
| 2026-08-10 | Cron autónomo cada 2 horas (minuto 17) + `workflow_dispatch`. | Suficiente para progreso continuo sin saturar CI; permite arranque manual. | Ventana de oportunidad cada 2h; si una sesión dura más, el session lock impide solape. |
| 2026-08-10 | Session lock por rama: `jules/autonomous-ordia` se bloquea durante la sesión; sin lock, nueva sesión no inicia. | Evitar dos agentes editando lo mismo. | El runner termina sin cambios si detecta lock activo (retry posterior). |
| 2026-08-10 | Failsafe `ORDIA_AUTONOMY_ENABLED` y verificación del archivo de bypass: si se desactiva, ninguna sesión nueva arranca. | Parada de emergencia independiente del código. | Apagar autonomía = crear/marcar archivo de bypass + desactivar variable. |
| 2026-08-10 | No reintentar indefinidamente; ante N fallos consecutivos, el workflow abre un ISSUE y la rama `jules/autonomous-ordia` queda intacta (revert si fuera necesario). | Evitar ciclos de agentes que se pisan y corrompen el repo. | Fallo visible y accionable para el humano. |
| 2026-08-10 | El workflow Jules usa `vars.ORDIA_AUTONOMY_ENABLED` como failsafe con valor por defecto ACTIVO (si la variable no existe o no es `false`/`0`/`no`/`off`, se lanza). | Coherente con el workflow previo (que lanzaba siempre) y con la decisión de autonomía continua; la parada explícita es la variable `false` o el archivo `AI_AUTONOMY/AUTONOMY_BYPASS`. | Requiere que el humano configure la variable solo si quiere DESACTIVAR la autonomía. |
| 2026-08-10 | Session lock por PR abierta: si hay cualquier PR abierta hacia `jules/autonomous-ordia`, no se lanza una nueva sesión. | Con cron cada 2h, evita que dos sesiones de Jules se solapen sobre la misma rama. | Una PR abierta de una sesión anterior pausa los ciclos hasta que se cierre/mergee; el humano puede cerrarla. |
| 2026-08-10 | El workflow verifica contra la API de Jules que la rama `jules/autonomous-ordia` exista en el source ANTES de lanzar; si no, el ciclo se omite (no falla el job). | La rama nueva puede tardar en sincronizarse con el conector de Jules; lanzar contra una rama inexistente fallaría en la sesión. | Primeros ciclos pueden ser no-op hasta que Jules vea la rama. |
| 2026-08-10 | Cron cada 2 horas en el minuto 17 (`17 */2 * * *`). | Suficiente para progreso continuo sin saturar CI; evita el minuto 00 y reduce colisión con otros jobs; `workflow_dispatch` permite arranque manual. | Ventana de oportunidad cada 2h. |
| 2026-08-10 | LA INFRAESTRUCTURA DE ORQUESTACIÓN VIVE EN `main`: `.github/workflows/ordia-autonomous-jules.yml` (scheduler), `.github/workflows/ordia-autonomous-merge.yml` (auto-merge) y `.github/workflows/android-ci.yml` (CI) se publican en `main` porque GitHub Actions ejecuta los schedulers desde la default branch. | El workflow nuevo NO estaba en `main` (solo en la rama autónoma) → el cron no corría. | Scheduler y auto-merge activos desde `main`; el código del rebuild sigue en `jules/autonomous-ordia` y NO se mergea a main. |
| 2026-08-10 | Auto-merge real y restringido: nuevo workflow `ordia-autonomous-merge.yml` mergea (squash, sin force) PRs hacia `jules/autonomous-ordia` cuando pasan 12 guardas (base exacta, no-main guard clause, no fork + patrón de rama Jules, no draft, mergeable, checks success, security checks success). | `AUTO_CREATE_PR` crea la PR pero NO la mergea; el session lock antiguo (cualquier PR abierta → no lanzar) habría bloqueado la autonomía indefinidamente. | PRs autónomas se fusionan solas tras CI verde; el humano NO tiene que mergear cada PR de Jules. |
| 2026-08-10 | El session lock distingue estados: sesión activa (API Jules) → skip; PR fallida → `proceed_with_failure_context` (la nueva sesión recibe el fallo); CI corriendo → `skip_ci_running`; PR lista → `skip_ready_for_merge`; ≥4 PRs → `skip_too_many_prs`; mismo área fallada ≥2 veces → `loop_warning`. | El lock antiguo (una PR abierta bloquea todo) era demasiado burdo y detendría el progreso tras la primera PR. | La autonomía continúa corrigiendo regresiones reales en lugar de detenerse. |
| 2026-08-10 | Jules NUNCA auto-mergea hacia `main`; el auto-merge tiene guard clause explícito (`base_ref == "main"` → MERGE PROHIBIDO) además de requerir base exacta `jules/autonomous-ordia`. | Proteger la base estable de cambios no revisados por humanos. | Sin camino automático `* → main`; solo el humano decide si algo llega a main. |
| 2026-08-10 | CI cubre también PRs hacia `jules/autonomous-ordia`: `android-ci.yml` ampliado (`branches: [main, jules/autonomous-ordia]`). | Los checks de la rama head solo existen si el workflow está presente; sin CI en las PRs autónomas el auto-merge esperaría forever. | Cada PR de Jules corre verify (tests+lint+assemble); sign/publish solo en push a main. |
| 2026-08-15 | El priorizador de tareas es UNO solo: `TaskRules.schedulingComparator(now)` (overdue desc → prioridad desc → dueAt asc → startAt asc → sortOrder → createdAt), reutilizado por `DayPlanner`, `WhatNowEngine` y `GuardianCoach` vía `nextBestTask`. | Evitar que cada pantalla ordene distinto y contradiga a "Qué hago ahora". | `WhatNowSuggestion.detail` explica la razón en español; tests de tie-break por fecha y sortOrder. |
| 2026-08-15 | El insight del Guardián se muestra como card en Hoy, descartable por el usuario con clave estable `eyebrow|taskId|title`, y se oculta si coincide con la sugerencia What Now actual. | El insight era inútil sin superficie de UI; la clave estable permite dedup sin perder el descarte. | Card con color por tono (GENTLE/FOCUSED/CELEBRATING/CALM); el fallback "TODO EN CALMA" no ocupa tarjeta. |
| 2026-08-15 | La conversión nota↔tarea es reversible y NO destructiva: crea la entidad destino y archiva la fuente (no la borra). | El usuario debe poder deshacer y conservar el original; el archivo da espacio de trabajo sin pérdida. | `NoteTaskConverter` en dominio + botones en TaskDetail/NoteEditor + tests de round-trip y blanco. |
| 2026-08-15 | Borrar una tarea borra TODO su subárbol en una transacción (`TaskTree.collectIds` BFS tolerante a ciclos), no solo la fila. | Sin FK self en el esquema Room, un `@Delete` simple dejaba subtareas huérfanas. | `TaskDao.delete` y `deleteSubtreeAndSelf` comparten la recolección; `TaskTreeTest` verifica transitividad/ciclos/raíz única. |
| 2026-08-15 | La migración Room 7→8 añade SOLO índices (`CREATE INDEX IF NOT EXISTS`) y queda versionada con `app/schemas/.../8.json`. | Índices para las consultas calientes sin romper datos existentes. | `version = 8`, esquema exportado (v2..v8 presentes en el repo). |
